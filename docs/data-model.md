# Модель данных

## Словарь терминов

| Термин курса | Термин моей темы |
|--------------|------------------|
| Ticket | Заявка на ремонт (Ticket) |
| Site | Оборудование (Equipment) |
| User | Пользователь (Сотрудник, Администратор, Техник, Руководитель) |

## ER-модель (сущности и связи)

**Ticket (Заявка)**
- `id` (PK, машинный идентификатор)
- `number` (человеческий номер, например REQ-2026-001)
- `title` (заголовок)
- `description` (описание)
- `status` (New, InProgress, Closed, Cancelled)
- `equipmentId` (FK на Equipment)
- `createdByUserId` (FK на User — кто создал)
- `assigneeUserId` (FK на User — назначенный техник, может быть пустым)

**Equipment (Оборудование)**
- `id` (PK)
- `name` (название оборудования)

**User (Пользователь)**
- `id` (PK)
- `fullName` (ФИО или логин)

**Связи:**
- Один справочник (Equipment) — много заявок (Ticket).
- Один пользователь (User) создаёт много заявок (Ticket).
- Один пользователь (User) может быть назначен на много заявок (Ticket).
- У новой заявки исполнитель может отсутствовать (`assigneeUserId` = NULL).

## Проверка 3НФ

Название оборудования хранится в сущности Equipment один раз. Ticket содержит внешний ключ `equipmentId`. При переименовании оборудования меняется одна строка, поэтому текст названия не дублируется в заявках.
